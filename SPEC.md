## Verified API contract

Read ../reference/live-webrtc.md and ../reference/live-delegation.md (downloaded official docs) before implementing. Relevant official URLs are https://developers.openai.com/api/docs/guides/voice-webrtc?api=live and https://developers.openai.com/api/docs/guides/live-delegation . Use the GPT-Live API, not Realtime legacy.

POST https://api.openai.com/v1/live/sessions with JSON {session:{model:'gpt-live-1',instructions:VOICE_PROMPT,delegation:{type:'responses',responses:{model:'gpt-5.6-terra',instructions:BACKEND_PROMPT,tools:[function definitions],parallel_tool_calls:false}}},transport:{type:'webrtc',sdp}}. Key server only. Responses backend can be configured by env; voice model remains gpt-live-1. Sanitize success response to session.id and transport.sdp. Browser creates microphone tracks/data channel `oai-events` before offer, waits for ICE, posts localDescription.sdp, reads result.session.id/result.transport.sdp. Wait session.started before app commands. No session.start, session.input_audio.append or legacy response events.

Live handles conversation; backend receives full ordered known guide catalog from dist/steps.js in its prompt and get_assembly_state tool for current state. Keep separate prompts. Model should interpret colloquial/incorrect names using current context, ask a brief clarifying question if multiple plausible actions remain, never fabricate unsupported features/instructions or claim it sees a camera. Navigation may act directly on clear reversible requests. Return actual results before describing successful actions. Do not upload PDF bytes, images, text or filenames. For unsupported uploaded PDFs, tell the model the manual is unrelated and prevent automatic mapping/claiming that the STRANDMON guide applies. Do not restore/replace an upload without user action. Never invent measurements/torque.

Tool loop: completed function calls come from response.event envelope containing event.type=response.output_item.done and item.type=function_call; retain delegation/response IDs (nested response.created). Collect calls even though response.completed has empty output. After all collected calls for that response are executed, send response.item.create with item {type:'function_call_output',call_id,output:JSON.stringify(result)} for each, then response.create once. Gate continuation on completion as documented, not each arguments delta. Validate names/arguments, catch errors, dedupe call IDs and don't replay mutations. No arbitrary URLs/selectors/code. Session generation fence ignores late old events/work. A user manually navigating while model work is pending must not be overwritten silently: capture a manual-action revision at delegation/response start, reject stale mutating calls with fresh state and clear reason. Keep human controls active.
